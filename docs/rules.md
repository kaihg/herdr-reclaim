# 現行規則（試玩基準）

這份文件整理 herdr-reclaim **目前實作的規則與數值**。它們是 MVP 試玩基準，之後可能調整；數值改動時，以這份文件與 `mod/herdr-reclaim/core/rules.js` 為準。`docs/proposal.md` 是當時的設計提案與決策紀錄（已由 `docs/city-growth-replan.md` 取代），不保證與現況一致。

#22 之後只有**一座共用城市**：所有 repo、space 與 session 的工作都進同一個倉庫、同一張地圖。舊版各 repo 城的遠征格、開墾點、研究羊皮卷、市集、加速與舊蓋房已經移除；程式不再讀寫 `cities/`（磁碟上的舊目錄留著，不遷移）。

## 地圖

- 一座固定的城，所有專案共用一張。城鎮中心是 2×2 共四格，不屬於任何建築。
- 開城就看得到城鎮中心周圍一塊 8×8 的土地（東北角還罩著迷霧），足以在與中心隔一格的位置放下 2×2 的市場；不用先開墾，也不必貼著舊建築。
- 地形固定：草地、疏林、碎石地可以蓋；深水與峭壁不行。地形不依 repo、space、session 或 provider 改變。
- **揭開**：一般建築完工時，占地往外 2 格永久揭開；哨站（#27）往外 5 格——同一處放一般建築或哨站都能下令，預定與施工中都不揭開。新揭開的地只要地形合法、沒有被占住，就能直接預定，不需另外取得建造權；揭開的深水與峭壁仍然不能放。
- 建築本身占著它的地，之後不能在上面再預定。

## 共用城市的基本收入（#23）

同一份本機使用者資料共用一座城、一個倉庫：換 repo、space、`/new` 或恢復對話都不會另開工地，也不會改變收入。

- 有效工作的一段**已結束回合**（活動紀錄裡 `interval_open` 到 `interval_close`）累積到共用倉庫的工作計量器。判準：互動的 root 與互動 fork 算工作，`role=child` 的 session 併進它的 root；print／headless 不納入；只算 non-cache input + output；用量有未知欄位的回合整回合不計。有沒有 commit 都算；成果的額外收成是 #24。
- 每滿 **10,000** 有效 token 收成一份建材：木材 ×3、石材 ×2、鐵料 ×1（規則版本 4）。餘數保留，頂欄的「工作 4000/10000」就是這個餘數。
- 同樣的工作切成長短不同的對話、換 provider、換專案，收成相同：只有 token 總量決定收入。
- 同一份工作只入帳一次：兩支 session（或兩個 space、恢復對話後的新 epoch）回報同一個用量來源時，第二筆不重複發。不同工作即使 token 數與時間相同，仍是兩份。
- 沒有指定建設目標時只累積庫存，不會有人替玩家花掉它。
- 共用城市從第一次啟用開始計收入；在那之前結束的回合不會倒灌（舊版各城歷史不遷移，見 #22）。

## 明確成果的額外收成（#24）

基本收入之外，留下可核對的成果會多一份建材；沒有成果時，原本的工作收入一分不少。

### 歸屬：這個 commit 是誰的？

hook 在 commit 發生時記下環境變數，用來判斷來源：

| 證據 | 結果 |
|---|---|
| `PI_SESSION_ID`（omp 的 bash 會注入） | 歸到這個 session；若是 child，往上歸到 root |
| `CODEX_THREAD_ID`／`CLAUDE_CODE_SESSION_ID` | 必須與 adapter 活動檔的 sessionId 完全相等、CLI 相同，才算歸屬 |
| 只有 terminal ID，或什麼都沒有（IDE、手動 commit） | **不收成**，只留下紀錄與原因 |
| 沒有安裝 hook 的 repo | 不收成 |
| 同一個 commit 的環境變數互相衝突（例如巢狀 CLI） | 來源不明，不收成 |

不提供人工補領，也不會猜測；來源不明的 commit 不影響你的程式碼，只是不發資源。遠端合併（`git pull`／merge 帶進來的提交）不可能有 session 歸屬，也不發。

### 發多少、怎麼去重

- 每個 commit 只跟它的**第一個父節點**比較（新 repo 的第一筆用 `--root`），列出改動的檔案；每個檔案依路徑歸成一類（大小寫不分，優先序由上往下，每個檔案只歸一類）：

| 類型 | 路徑判定 | 分類 |
|---|---|---|
| 測試 | `**/tests/**`、`**/__tests__/**`、`test_*`、`*_test.*`、`*.spec.*`、`*.test.*` | test |
| 文件 | `*.md`、`*.rst`、`docs/**` | document |
| 設定 | `*.json`、`*.ya?ml`、`*.toml`、點開頭的檔案 | config |
| 程式 | 以上都不是 | code |

  預設不計入：generated、vendor、依賴目錄、lockfile，以及內容沒變的 rename。二進位檔與大檔只看路徑和 blob ID，不讀內容。
- **發多少**：每一個歸屬確定、發生在啟用之後、且帶來新內容的 commit 額外收成一次木材 ×3、石材 ×2、鐵料 ×1（規則版本 5 起；試玩參數，不看 commit 大小）。空 commit、只改排除路徑、或內容已經在帳上的 commit 不發。
- **不重複發**：同一份內容只發一次——同一個 commit 從兩個 space 抵達、重開再重播、或 rebase／amend 換了 sha 但內容已在帳上，都只有第一次入帳。claim 是「repo 身分 + 路徑 + 結果 blob」，刪除用 first-parent 的 blob。第二個不同且合格的成果仍各發一份。
- 成果加成與基本收入進同一個共用倉庫，頂欄的庫存就是兩者的總和。

## 選址與預定地（#25）

畫面就是共用城市：庫存常駐頂欄，左側是建築與唯一目標，中間是地圖，右側是選取格或整棟預覽。

- **先選建築、再看位置**：左側列出建築、整片占地、配方與完工揭開幾格。選好之後地圖標出全部合法錨點，點一格顯示整棟占地。
- **可建的地**：草地、疏林、碎石地。整棟占地每一格都必須已揭開、可建，而且沒有被其他建築、城鎮中心或預定地占住；任一角碰到深水、峭壁、迷霧或已占用的位置，整棟都不能放。同種建築在疏林、碎石地上的配方與工期與草地相同。
- **預覽就是下令**：畫面的整棟預覽與帳本的前提檢查用同一個判準，綠色代表下得了令，紅色那幾格就是不合法的那一角。
- **一次只有一個目標**：已有預定地時，第二個目標整筆被拒。兩個視窗同時送出時最多一個生效，被拒的一邊不會留下半片占地。
- **指定位置不付料**：預定地保留整片占地、庫存不預扣；「還缺」是配方減掉現有庫存的差額。材料備齊才支付並開工（#26）。
- **重開與跨 space**：預定地寫在共用帳本裡，切 repo、換 space、重開 herdr 或做 checkpoint 之後都是同一個目標。

## 備料、施工與完工（#26）

預定之後照常工作就好，不用回來按領取或確認完工。

- **自動開工**：哪一筆收成（基本收入或成果加成，來自哪個專案、哪段對話都一樣）讓庫存足以支付預定時的完整配方，就自動開工、一次付清。開工時間是材料真的到齊的時間：入庫建材裡最晚的那一筆（晚到的較早工作不會讓工期回溯），早於下令就從下令那一刻起算。下令時庫存已經夠，就在下令那一刻開工。
- **建築表**（規則版本 8，試玩參數）：

| 建築 | 占地 | 配方 | 工期 | 完工揭開 |
|---|---|---|---|---|
| 民居 | 1×1 | 木材 20、石材 10 | 3 分鐘 | 2 格 |
| 工坊 | 2×1 | 木材 30、鐵料 5 | 5 分鐘 | 2 格 |
| 哨站 | 1×1 | 木材 25、石材 15、鐵料 5 | 6 分鐘 | 5 格 |
| 市場 | 2×2 | 木材 40、石材 20 | 8 分鐘 | 2 格 |
| 書庫 | 2×2 | 木材 20、石材 20、鐵料 5 | 8 分鐘 | 2 格 |

  只看建築種類；同一種建築放在草地或疏林、碎石混合地，配方與工期相同。開工後植被與碎石讓位，占地畫成工地。
- **完工**：開工時間加工期就完工，關著 herdr 的時間也算；晚打開畫面不改變完工時間。完工立即啟用，預定地交還，城市回到「沒有建設目標」。
- **只扣一次**：開工與完工各綁著同一個建設目標。兩個視窗同時補齊材料、同時看到工期到、重開或重播，都只有一筆開工（一次付料）與一筆完工（一棟建築）。
- **完工之後只存料**：後續工作只增加庫存；即使庫存已足夠再蓋一棟，也不會有人替玩家選下一棟或付料。
- 地圖上三個階段畫法不同：預定地是強調色虛線（地面仍是原本的地形），施工中是工作色斜線與「施工·」標籤，完工是完成色實線、建築與名稱。

## 額度

- 只顯示 provider 或 CLI 明確回報的數字（`omp usage --json --redact` 的輸出）；拿不到、沒有回報項目、帳號沒有額度或資料過期，都顯示「未知」。不推算、不填 0 或 100，也不因額度擋住你。
- 額度是帳號層級、所有 workspace 共用：`quotas.json` 與「上次嘗試時間」都是全域檔案，不管開幾個視窗，每 5 分鐘最多查一次；按「更新額度」可以立刻抓。
- 顯示在共用城市左側的「行會人力（provider 回報）」。

## git hook

開啟自動收成會在該 repo 安裝三個 hook：`post-commit`、`post-merge`、`post-rewrite`。

- 只在本機寫一筆紀錄（`commits/<sha>.json`），不連網、不修改你的 commit，永遠以 exit 0 結束。
- 不使用全域 `core.hooksPath`。repo 自己設了 `core.hooksPath` 就裝在那裡，否則裝在 common dir 的 `hooks/`（worktree 共用）。
- 已有同名 hook 時，改名保留，新的 hook 先呼叫它。
- 用 husky、或 hooks 目錄納入版本控制的 repo，不會自動安裝，會說明原因。
- 共用城市對每一個看過的 repo 問一次（左側的自動收成區塊，最多列四個）；隨時可以停止，會還原原本的 hook。
