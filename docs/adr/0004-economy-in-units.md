# 經濟以「份」計：人口為長期目標，維護在進帳時扣

正式城市在 2026-11-26 一天內進帳約 163 份、蓋完 6 棟，之後庫存停在目錄需求的 2.6／4.2／10.4 倍，頂欄只剩「沒有建設目標」。同一天單回合 token 從 365 到 95 萬，差 300 倍以上，任何「每天幾份」的校準都對不準。問題不在產出太多，而在建材只有一個一次性出口（建築），城市沒有需求、沒有會隨規模成長的消耗，玩家也沒有分配產出的槓桿。

因此改成完整的資源循環，而不是調收入：

- **一律以份計，不以日計。** 成本、門檻與成長曲線都以累積的份表示；用得多的人只是走同一條曲線比較快，不替每個人校準節拍。
- **人口是長期目標。** 民居容納人口；其他建築要有人力才運作。時代是人口門檻上的里程碑，一次消耗大量建材，解鎖新建築。
- **維護在進帳時扣。** 城市越大，每次進帳先扣的比例越高，淨收入成長變慢；比例有低於 100% 的上限，輕度玩家不會卡在零成長。
- **離開不衰退。** 沒有進帳就不扣維護，一週不開回來城市原樣；從 journal 重播時，維護只依每筆進帳與當時的城市計算。
- **產出依地形。** 產出建築的產量看周圍地形（例如伐木場靠林地），這是玩家分配產出的槓桿，也讓選址有取捨。
- **探勘是第二步。** 揭開改為可重複、距離越遠越貴的消耗；第一步先做維護與人口。

## Considered Options

- **控制產出**（每日固定份數、按個人中位速率定價、次線性收入、每回合定額）：只改變建材來得多快，庫存仍只有建築一個出口；而且都要用「日」當單位，和遊戲內時間無關。不採用。
- **按現實時間扣維護或讓建築衰退**：能平衡，但會懲罰離開，和「城市安靜就該看起來安靜」衝突。不採用。

## Consequences

- [ADR 0002](0002-income-from-work-only.md) 的「收入只看工作量」管的是外部訊號：進帳只看工作量，不看 commit 或成果。遊戲內的人口、維護、地形加成改變的是進帳之後的分配，不違反它。
- 收入公式（`workYieldOf`）會依城市狀態改變，所以規則版本要進位，舊 journal 照當時的規則重播。
- 畫面只顯示人口與一個「維護 x%」，不列每棟建築的帳；超過這個粒度就是在做帳務系統。

## 細部決定（2026-11-26）

- **城鎮中心是最小的通用產出**：每份進帳固定給少量三種建材，不隨城市規模成長；大部分建材來自產出建築。
- **人力自動分配**：人口不足時，最後蓋的建築先停工，地圖標「缺人」。玩家的決定是先蓋民居還是先蓋產出建築，不逐棟指派。
- **既有建築重新分工**：民居給人口；工坊改產鐵（碎石、峭壁旁較高）；新增伐木場（林地）與採石場（碎石）；市場以損耗換料，本身也是出口；書庫是升級時代的前置；哨站維持到探勘上線。
- **現有城市可以重置**（2026-11-26 更新，取代原本的「保留現城」）：道路與分區改版（[ADR 0005](0005-zoning.md)）之後，不要求遷移現有的建築與庫存；新規則從新帳本開始，舊 journal 留在磁碟上、不讀也不改。測試用的起始庫存直接寫進固定情境，不靠真實進帳。
- **時代先定三段**：村落 → 市鎮 → 城市；第一版只做村落升市鎮。
- **解鎖與換料**（2026-11-26）：現有建築用人口門檻分段解鎖，暫定市場 20、工坊 55、書庫 88，升市鎮要 100 並且有書庫，實際數字等地形與道路定案後重跑模擬；市場自動以 2 換 1 補手動佇列第一項與自動施工缺的料，畫面只顯示「市場換了多少」。
