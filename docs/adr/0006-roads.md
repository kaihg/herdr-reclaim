# 道路：分區的施工範圍由玩家鋪的路決定

[ADR 0005](0005-zoning.md) 的模擬顯示，分區自動施工之後，玩家打開城市的頻率不再影響結果，但也沒有決定可做：新揭開的地自動劃區、施工順序固定、一次性建築只有 4 個。玩家需要一個很久才做一次、而且真的有取捨的決定。

決定：玩家鋪道路，分區只在道路附近自動施工。道路延伸多遠，能用的土地就多遠；往哪個方向延伸、沿線做什麼用途，是玩家的決定。

- **玩家指定起點與終點，路徑由城市決定。** 確認前顯示路徑預覽與總成本；單條道路有長度上限（初值 12 格）。
- **道路走建設佇列**（[ADR 0003](0003-construction-queue.md)）：FIFO、排到隊首才付料、開工前取消不收費、開工後不退料。撤除先不做，所以畫錯的路改不回來，預覽與成本顯示是必要條件。
- **只能鋪在已揭開的可建地面。** 道路格取代原本的地形，不再算進產出建築的周邊資源格；深水要用橋（成本是一般道路的數倍），峭壁不能鋪。
- **道路不揭開周圍。** 看見由建築與哨站負責（揭開），能蓋由道路負責（連通）；要往遠處延伸，得先靠哨站或邊緣的建築看過去。
- **分區每格離最近的道路不超過 2 格才自動施工**，超出的部分保留分區但暫不施工。
- **分區的用途怎麼決定：尚未定。** 曾提議下道路時一併選沿線用途，但使用者想不出順暢的操作流程；先比較不需要劃區的做法（用途由路線經過的地形與需求決定）。
- 新規則從新帳本開始，不遷移現有城市（見 ADR 0004）。

## Considered Options

- **道路取代哨站作為揭開手段**：不採用。揭開與連通分成兩條軸之後，哨站仍有「看得遠」的角色，兩者形成「看見 → 鋪路 → 劃區」的循環。
- **分區只要碰到一格道路就整片算數**：不採用。一條路旁的小格子可以帶出整片大分區，鋪路沒有取捨。
- **下道路時一併選用途／道路與分區各自下單**：兩種都還在比較，取決於能否設計出順暢、好理解的操作；各自下單會出現「只鋪路沒用途」或「只劃區沒路」兩種什麼都不會發生的狀態。

## Consequences

- ADR 0004 的「探勘第二步」由道路接手「可重複、距離越遠越貴的消耗」這個角色；揭開仍由建築與哨站負責。
- 需要連續的河才能放橋，需要成片的疏林與碎石才能分區產出：地形生成要先重做（見 `docs/city-design-backlog.md`）。
- ADR 0005 的模擬數字是在零碎地形、沒有道路的前提下跑的，只能當暫定值，地形與道路定案後要重跑。
- 畫面頂欄要顯示目前最缺的一項（缺人、缺木、缺石或缺鐵），只用文字、不給數字，讓玩家知道往哪個方向發展；沒有這個提示，玩家只能亂猜。
- 維護的規模 N 不計道路；鋪路是玩家的擴張決定，不該再被維護壓抑（[ADR 0004](0004-economy-in-units.md)）。
