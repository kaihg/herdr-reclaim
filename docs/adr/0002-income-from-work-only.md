# 收入只看工作量，commit 不再加碼

[ADR 0001](0001-shared-city.md) 之後，基本收入已按有效 token 發放，有沒有 commit 都照算；commit 只是在基本收入之外再發一份建材（#24）。正式帳本裡這份加碼只占總收入的 2.9%（274 份建材中的 8 份），代價卻是：每個 repo 都要在 `.git/hooks` 裝記錄器並逐一同意；要維護跨 CLI 的 session 歸屬規則（環境變數比對、OMP `changes.jsonl` 配對、巢狀 CLI 衝突判為來源不明）；非 git 專案與不 commit 的使用者會看到一項永遠拿不到的收成。它也擋不住「燒 token 換資源」：加碼不是收入門檻，燒 token 本來就領全額，真正的上限是 token 本身的成本與額度。

因此停止產生 commit 收成，移除 hook 安裝、commit 歸屬與證據收集；所有使用者在同樣工作量下拿到同樣收入。代價是城市不再區分「留下可核對成果的工作」與「只有工作量」，「城市隨真實成果成長」的定位改為「城市隨工作累積」。

- 帳本裡已落帳的 `achievement` 照常重播，庫存不因升級改變；只是不再產生新的。
- 已裝在各 repo 的記錄器由 mod 提供一次性全部移除，移除前列出受影響的 repo，按下才動；被串接的原有 hook 會還原。
- 曾考慮改由 adapter 在回合前後比對 HEAD 來偵測 commit，省掉 hook。不採用：仍然只認 git，同一 repo 同時開兩個 session 時歸屬不明，歸屬邏輯一樣要留著。
- 若日後要讓城市呈現成果，另做不影響經濟的紀錄，不恢復這套歸屬。
