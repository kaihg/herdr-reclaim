# 分區：玩家劃定用途，城市依進帳自動施工

[ADR 0004](0004-economy-in-units.md) 改成以份計之後，原型把「玩家多久打開一次城市」納入模擬：每筆進帳都下令時，重度與輕度玩家升市鎮相差 28 份；每 2 小時看一次相差約 330 份；一天看一次時，重度玩家 1,500 份內升不了市鎮，庫存堆到累計消耗的 5～10 倍。重度玩家一天約 215 份，打開一次卻只能排 3 項，進度變成由打開次數決定，多做的工作只變成庫存，實質違反 [ADR 0002](0002-income-from-work-only.md)。把佇列上限調到 6、12、20、40 都壓不回來：貴的項目排在前面會擋住後面全部。

因此改用分區：玩家劃定區塊用途（住宅區、伐木區、採石區、工坊區），城市在進帳時用庫存在區內自動蓋民居與產出建築。只出現一次的建築（市場、書庫、哨站）與升時代仍由玩家手動排進建設佇列。玩家的決定從「每一棟蓋在哪」變成「這一片做什麼用」，可以很久才做一次，進度回到只看工作量。

## Considered Options

- **接受「進度看打開次數」**：重度玩家堆出上萬庫存，就是 ADR 0004 要解決的問題。
- **把經濟做粗**：每個目標至少約 72 份才能讓一天看一次的重度玩家跟上，1,500 份只剩約 20 棟，輕度玩家約 3.4 天才完成一棟。
- **城市自動排下一項**：數字等同每筆都看，但玩家沒有選擇，只剩確認按鈕。

## Consequences

- [ADR 0003](0003-construction-queue.md) 的「完工之後不自動加項」改為只適用手動佇列；分區內的自動施工另有規則，且不得吃掉手動佇列隊首等待的材料。
- 分區的價值取決於地形能不能成片；現行逐格雜湊的地形太零碎，地形生成要重做（見 `docs/city-design-backlog.md`）。
