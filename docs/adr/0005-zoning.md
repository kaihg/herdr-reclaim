# 自動施工：城市依進帳在道路沿線蓋產出建築與民居

[ADR 0004](0004-economy-in-units.md) 改成以份計之後，原型把「玩家多久打開一次城市」納入模擬：每筆進帳都下令時，重度與輕度玩家升市鎮相差 28 份；每 2 小時看一次相差約 330 份；一天看一次時，重度玩家 1,500 份內升不了市鎮，庫存堆到累計消耗的 5～10 倍。重度玩家一天約 215 份，打開一次卻只能排 3 項，進度變成由打開次數決定，多做的工作只變成庫存，實質違反 [ADR 0002](0002-income-from-work-only.md)。把佇列上限調到 6、12、20、40 都壓不回來：貴的項目排在前面會擋住後面全部。

因此重複性的建築（民居與各種產出建築）改由城市在進帳時自動施工，玩家不逐棟下令。只出現一次的建築（市場、書庫、哨站）與升時代仍由玩家手動排進建設佇列。玩家的決定從「每一棟蓋在哪」移到更少、更久才做一次的地方：道路往哪裡延伸（[ADR 0006](0006-roads.md)）、一次性建築放哪裡。

原本的版本是玩家劃定住宅、伐木、採石、工坊四種用途的分區。使用者想不出順暢的操作流程，所以不做劃區：用途由城市依需求與路旁的地形決定（見 ADR 0006）。

## Considered Options

- **接受「進度看打開次數」**：重度玩家堆出上萬庫存，就是 ADR 0004 要解決的問題。
- **把經濟做粗**：每個目標至少約 72 份才能讓一天看一次的重度玩家跟上，1,500 份只剩約 20 棟，輕度玩家約 3.4 天才完成一棟。
- **玩家劃定用途（畫筆）**：決定留得住，但在窄 pane 裡很難點準，也沒有想出好理解的流程。不採用。
- **城市完全自動排下一項**：數字等同每筆都看，但玩家沒有任何決定。由道路補上決定，見 ADR 0006。

## Consequences

- [ADR 0003](0003-construction-queue.md) 的「完工之後不自動加項」改為只適用手動佇列；自動施工另有規則，且不得吃掉手動佇列隊首等待的材料。
- 原型（Ze）顯示：自動施工之下，一天看一次與每筆都看的結果完全相同；但新揭開的地自動劃區、施工順序固定，玩家沒有決定。這是引入道路的原因。
- 原型的數字是在零碎地形、沒有道路的前提下跑的，只能當暫定值；地形與道路定案後要重跑。
